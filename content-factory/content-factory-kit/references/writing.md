# 阶段二 · 写作与改稿规范

配套 `content-factory-kit` 支路 A。本份管**写作与改稿**：怎么定声道、按什么骨架写、
标题怎么起、改稿时哪里绝对不能动。

## 一、开工前先定声道（这一步决定后面全部写法）

同一个作者按题材切换两套嗓子，这是识别度的核心。
**写第一个字之前先判定声道，判定错了后面全废。**

| | **A 声道 · 专业理性** | **B 声道 · 朋友闲聊** |
|---|---|---|
| 什么时候用 | 厂商 / 产品稿、适配与踩坑长文、客户案例、产品解析与评测 | 自己的项目、脑洞随笔、开源项目评测、碎碎念、教程连载、日常 |
| 语气 | 克制、判断明确、术语准确 | 口语、自嘲、情绪外露 |
| 人称 | 少用「我」，多用「本次 / 本文 / 适配中」 | 高频「我」，可以说「我还是个菜鸟」 |
| 段落 | 3–6 句成段，句间走因果链 | 常见一句成段，短促跳跃 |
| 表情梗图 | 几乎不用 | 大量使用 |
| 标志 | 分层表格、清点式小标题、**能力边界**、环境声明 | 心路历程、翻车现场、热梗、邀请互动 |

**判定规则**：给厂商 / 产品写的、要显专业的 → A；写自己的项目、想法、翻车、玩 → B。

**两者绝不混用**——A 里忽然卖萌，或 B 里忽然「综上所述」，会立刻失味。
这是自查第一条。

> 这一条是**通用写作方法论**，不依赖任何具体作者。但两套嗓子各自的「具体长相」
> （用哪些语气词、什么程度叫自来熟）是个人特征，得你自己定 → 见 `references/style-guide.md`。

## 二、通用骨架（六拍）

```
① 标题：两段式 / 亲测式（见 §六）
② 开场：3 句内出现钩子（具体场景 / 数字 / 反常识结论），绝不「XX 是一种……」定义开场
③ 主体：编号大节（一、二、三…），节内小标题用口语化短语
④ 支撑：表格 / 清单 / 代码 / 截图 —— 每个论断后面跟一个证据
⑤ 注意点：易错处单独标「注意：」，或独立成节
⑥ 收尾：总结回扣 + 观点金句 + 互动或下期预告
```

## 三、七体裁骨架卡（先认体裁，再套骨架）

| 体裁 | 骨架 | 必备元素 |
|---|---|---|
| **踩坑复盘** | 真实故障场景 → 原理剖析 → 错误模式速查表 → 审查清单 → 最佳实践 → 总结 | 具体报错原文、正误对照、环境声明 |
| **适配 / 实战长文** | 为什么选它 → 技术路线表 → 分阶段推进 → 关键问题清点（1.2.3.4.5.）→ 构建运行 → 能力边界 → 总结 | 分层表格、真机截图、诚实说局限 |
| **产品解析 / 评测** | 行业痛点 → 产品定位 → 分能力拆解 → 实测数据 → 适用 / 不适用场景 | 数字对比、基准测试、对手横评 |
| **客户案例** | 摘要先行 → 客户背景（量级）→ 难点 → 方案分层 → 量化收益 → 价值收尾 | 硬数字（80TB / 1200 个站点 这种） |
| **资讯评论** | 刷到什么 → 第一反应直说（可吐槽）→ 编号列惊讶点 → 亲自验证 → 观点输出 → 展望 | 「第一反应：又来一个吹的？」式坦白、截图佐证 |
| **教程连载** | 片头模板 → 打招呼 → 分步 + 截图 → 「注意：」→ 总结 + 下期预告 | 期数、系列名、预计时间 |
| **随笔 / 脑洞** | 生活场景切入 → 情绪流淌 → 引出作品或结论 → 邀玩 | 具体感官细节 |

## 四、篇幅配比（按比例分配，不要平均用力）

| 体裁 | 配比 |
|---|---|
| 技术长文 | 开场 8% / 主体 70% / 问题清点 12% / 边界与总结 10% |
| 资讯短评 | 开场 10% / 惊讶点 35% / 验证 30% / 观点结论 25% |
| 教程 | 片头 8% / 前言 10% / 分步 65% / 总结预告 17% |

正文区间 1500–2500 字，**起稿按 ≤2400 字**，超限会被打回重压。

## 五、段落与句子

### 节奏

- **一句成段是常态**，尤其情绪段（「就这一下，把我问住了。」）
- **三段递进式自白**：摆问题 → 自我拆穿 → 给动作
- **专业段相反**：3–6 句成段，句间走因果链
- **转折词偏爱**：说白了、其实、不过、结果、注意、相反、换句话说
- **数字落地**：形容词后必跟量级——不说「很快」，而说「几秒就能拿到结构化数据」

### 语气

- 语气词收尾（按你自己的习惯选，不要硬凑）
- 自嘲坦诚：承认自己是新手、承认摆烂、承认 FOMO
- 技术拟人化：「优化器心里变成了 INNER JOIN。它没告诉你，直接改了。」
- 网感词**点状使用、不铺满**：白嫖、上头、翻车、开箱 这类，一篇两三处就够
- 观点加限定：「我个人感觉这个项目意义还是很大的」「如果真像作者声称的那样」

### 明确避免

- 官腔：综上所述、众所周知、赋能、抓手、生态闭环
- 排比堆砌、空喊口号、无依据的绝对化（「史上最强」）
- A 声道里突然卖萌，B 声道里突然总结陈词

### 签名式元素（这些是个人特征，自己定）

收尾的固定签名、格言、署名格式、连载期数习惯、互动引导方式——
**这些都属于「判断标准」那一半**，本规范不给值。
`references/style-guide.md` 讲了怎么把它们从你的作品里提炼出来。

## 六、标题规范

### 长度与形态（**这是实测区间，不是硬规则**）

对中文技术 / 内容平台的成熟期作者做过一批实测，结论大致是：

- 标题长度中位数约 **28 字**，25–34 字与 35 字以上合计占三分之二——**偏长，信息密度高**。
- 「主标题：副标题」两段式的比例在近两年明显上升（早期 2% → 近两年 60% 以上）。
- 带具体数字的约占五分之一；问号悬念句是近年新增手法。
- 早期常见的「【栏目前缀】+ 短教程体」在新内容里基本弃用（除非本来就是连载教程）。

> **注意**：上面这些是「别人样本」的结论，只能当参照系。
> 你自己的一批作品量出来可能是另一个形状——去 `references/style-guide.md` 自己量一遍。

### 五个公式（按常用度排序）

1. **冒号两段式**（最常用）：`主标题：副标题补充价值 / 悬念`
   例：「某工具 Operator：声明式部署、扩缩容与备份监控一体化」
2. **第一人称亲测式**：「我用 X 搭了一个 Y，从关键词到初稿一条链路跑通」
3. **口语悬念问句**：「如果世界按下 Ctrl+Z 会怎样？」
4. **动作 + 夸张修辞**：「让异构增量同步飞起来！」「白嫖 Cloudflare，给我的笔记软件搭个永久免费图床」
5. **全记录 / 实录体**：「某工具某平台版适配全记录：从 Qt 桌面工具到 ArkTS 原生应用」

**标题爱用动词**：干、搞、跑通、踩坑、开箱、速通、飞起来。
**数字必须具体**（800 star、5 个 Agent、25 分钟），这是信息密度的主要来源。

### 标题禁忌

短平无信息（「浅谈 XX」）、无数字无悬念的纯名词短语。

### 一次给多个标题时

给足数量（任务卡要几个给几个），并**标注每个适合哪类读者 / 哪个平台**；
同一篇的多个标题要在**角度**上真的不同，不要同义改写。

## 七、改稿细则（本份的核心增量）

### 铁律：改稿不可动清单

改稿**只动表达，不动事实**。以下内容一个字都不能改，改了就是出错：

- 数字、时间、版本号、行数、金额
- 链接，以及研究阶段留下的「（来源：xxx）」标注
- 「【待核实：xxx】」标记（**不能因为读起来不顺就把它删了**）
- 声道（A 稿不要改成 B 腔，除非任务卡明确要求换声道）
- 证据（表格 / 代码 / 命令 / 截图占位）
- 「注意：」标记的易错点内容
- 专有名词、代码标识符、API 名、产品名的大小写

改完必须回读一遍，确认没有把论证链删掉一环、没把限定条件删成绝对断言。

### expand（扩写）

按优先级补，**不要用形容词和排比扩字数**：

1. 把模糊量级补成具体数字（查不到就标【待核实】，不要编）
2. 给抽象判断补一个真实例子、场景或对话
3. 补正误对照（错误做法 → 现象 → 正确做法）
4. 补对照表（vs 上一代 / 竞品 / 不同方案）

### shorten（缩写，目标原文 60% 左右）

**删除顺序**（从先删到后删）：

1. 铺垫与背景重申（开头已经说过的不要再说）
2. 重复过渡句（「接下来」「那么」「说到这里」）
3. 同义并列（三个形容词留一个）
4. 空泛形容词与空词
5. 客套收尾

**必须保住的**（删到这里就停）：数字与来源 → 判断结论 →「注意：」易错点 →
代码与命令 → 表格结构 → 能力边界声明。

删完回读，**如果论证链断了，把上一步删掉的东西加回来**。

### stronger（增强观点）

把「可能 / 或许 / 一定程度上」改成明确判断，并补一句理由。

**但保留必要的限定条件**——把「在 X 场景下能省一半时间」改成「能省一半时间」是错的，
那不是增强观点，是造假。

不要变成断言式说教（「你必须」「唯一正确的是」）。

### deai（减少 AI 味）

见 `references/deai.md`（10 类 AI 味黑名单 + 逐类改写对照）。
这个动作要求**额外输出**：改完后单独列出「我改掉了哪 5 类 AI 腔」，
每类给一组「原文 → 改写」对照。**别漏这一步**。

### spoken（改得更口语化）

口语化 ≠ 轻浮。程度由声道决定：

- B 声道可以放语气词、自嘲、反问；
- A 声道只能把长句拆短、把被动改主动、把术语讲成人话，**不要加语气词卖萌**。

### openhead / openend（优化开头结尾）

- **开头**：第一句就给具体场景、具体数字或反常识结论，**不要背景铺垫**。
  给 3 个不同版本，并标注各适合什么内容类型。
- **结尾**：回到开头的具体场景形成呼应，给可执行的建议或一个开放问题，
  **不要空泛升华**。给 2 个版本。

## 八、交付前自查清单

1. 声道选对了吗？全篇有没有串味？
2. 标题是两段式或亲测式？有具体数字或悬念？没有「浅谈」类空标题？
3. 开场 3 句内有钩子（场景 / 数据 / 反常识）？没有定义句？
4. 主体用了编号大节 + 口语化小标题？
5. 每个论断后面有证据（表格 / 截图 / 数据 / 代码）？
6. 易错点用「注意：」单独标了？
7. A 声道稿写了「能力边界 / 代价」？B 声道稿有情绪和自嘲？
8. 结尾有总结 + 互动或下期预告？
9. 形容词后面跟了量级，而不是「很快 / 很大 / 显著」？
10. **改稿任务：数字、来源标注、「待核实」标记、证据、声道，一个都没被动过？**
11. 正文在 1500–2500 字区间？（数一遍，别估）
12. 结果摘要写清了「这次做了什么 / 改了哪几处 / 落到哪个字段」？

## 九、失败与降级

| 情况 | 处置 |
|---|---|
| 只有标题，没有研究资料和大纲 | 不要凭空写长文；按标题能确定的范围写短稿，并在结果摘要注明「缺研究资料，建议先跑研究」 |
| 目标记录已删除 / 是测试残留 | 标记失败 + 说明，不要写回 |
| 现有正文为空却要求改稿（缩写 / 去 AI 味） | 明确标失败：**无可改内容**；不要自己造一篇再改 |
| 写到一半发现研究资料与正文自相矛盾 | **以研究资料为准**，在结果摘要里标出矛盾点，不要静默选一个 |
| 篇幅要求与内容量不匹配 | 宁短勿灌水；结果摘要说明「按信息量写到 X 字，未凑到 Y 字」 |

## 十、常见坑

- **别把速用指令当成全部规范**。任务卡里注入的通常是几条速用指令；
  体裁骨架、篇幅配比、改稿细则、AI 味黑名单都在本份里。
- **改稿不是重写**。收到扩写 / 缩写 / 去 AI 味时就地改，不要把整篇换成自己的写法——
  那会让改稿后风格断裂。
- **「待核实」不能顺手删**。它看着像瑕疵，实际是必要的诚实标记。
- **缩写时别删论证链**。删到「结论还在但不知道为什么」就是删过头。
- **A 声道稿的「代价」是必写项**，不是可选项——「只讲优点不讲代价」是反模式。

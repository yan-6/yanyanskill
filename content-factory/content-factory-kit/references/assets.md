# 阶段五 · 资产沉淀规范

配套 `content-factory-kit` 支路 A。沉淀不是给这篇文章写结语，是给**下一篇**备料。
本份规定「提炼成什么样才配存进素材库」。

## 一、为什么要有这个闭环

内容工作台的通常做法是：**每次生成任务卡时，把素材库里方法类资产取前 N 条注入提示词**
（N 常见是 10，每条还会被截断到 200 字左右）。于是：

- 资产**写得空** → 注入的是废话，下一轮产出退回通用腔；
- 资产**写得像本篇总结**（「这篇文章用了总分总」）→ 换个选题就不能用，等于没沉淀；
- 资产**条数超过注入上限** → 只有排在前面被带上，后面的白存。

一句话：**验收标准不是「概括得像」，而是「下篇能直接照着做」。**

> 具体注入多少条、截断到多少字、按什么排序，**看你自己工作台的实现**
> （在前端代码里搜注入函数）。如果它按「表返回顺序」而不是按星级排序，
> 那么**排序就是生死线**，你要么改排序，要么把最好的放最前。

## 二、合格资产的 5 条硬门槛

逐条过，有一条不过就别入库（宁少不灌）：

1. **脱敏**：不出现本篇独有的人名 / 产品名 / 具体数据——
   除非它本身就是可复用素材（案例库、金句除外）。
2. **可迁移**：把句子里的本篇主题词删掉，句子仍然成立。
3. **带触发条件**：必须写「什么时候用 / 什么时候别用」。
   只有做法没有边界 = 不合格。
4. **带证据锚点**：说明它在本篇哪里体现了（引用原文片段，不必全引）。
5. **单条不超长**：注入时通常只取前 200 字，**结论必须在前 60 字内自成一句**，
   补充说明往后排。写超了后半段注定看不到。

## 三、七类资产各自的合格线

| 动作 | 资产分类 | 合格线（缺一不可） | 不合格的典型 |
|---|---|---|---|
| `sed-method` | 方法论 | 方法名 + 本篇体现位置 + 适用/不适用 + **可套用的句式或骨架** | 「要注意结构化输出」这类没有做法的口号 |
| `sed-topic` | 选题方法 | ≥3 条规则，每条带**「看到什么信号就出手」的判据** + 不适用类型 | 「选题要有价值」正确但无法执行 |
| `sed-struct` | 文章结构 | 每节职能 + **字数占比** + 可直接复制的骨架 + 适合的内容类型 | 只写「开头-正文-结尾」的空模板 |
| `sed-prompt` | Prompts | 用途 + 模板正文（变量用 `{{ }}`）+ 一次真实填充示例 + 跑偏时加哪句约束 | 只有说明没有模板正文 |
| `sed-skill` | Skills | 技能名 + 触发条件 + **分步表格（输入/处理/输出）** + 质检点 + 失败环节与兜底 | 只描述「可以做成一个技能」 |
| `sed-quote` | 金句 | **逐字来自原文**（不得改写事实）+ 出自哪节 + 适合放哪 + 改写版 | 编造原文里没有的句子 |
| `sed-case` | 案例库 | 素材名 + 素材正文 + 说明什么观点 + **还能用在哪些主题** + 是否需标出处 | 只写案例名，没有可复用正文 |

**金句的二级分类**（写在「类型」字段里，这套分类经过实测好用）：
观点 / 泼冷水 / 共情 / 结论 / 观察 / 能力边界 / 自曝。

用途区别：**自曝、共情**类多在 B 声道；**能力边界**类固定收尾用；
**观点、结论**类可当封面文案。

详细对照示例见 `references/asset-examples.md`。

## 四、命名规范（决定能否被检索与去重）

`素材名称` 既是去重键，也是人肉检索的唯一抓手：

| 分类 | 命名式 | 好例 |
|---|---|---|
| 金句 | `「金句原文」`，保留原句引号 | 「语法兼容不等于性能一致。」 |
| 文章结构 | `X式｜逐节流程用 ｜ 分隔` | 全记录式｜为什么做 → 技术路线 → 分步实现 → 踩坑 → 能力边界 |
| 方法论 | `做法名（括号补一句人话）` | 结构化输出不能只靠 Prompt（四层兜底） |
| 选题方法 | `「系列名」+ 方法名` 或 `X法（判据）` | 「X 全记录」系列化选题法（一个平台缺口 = 一个系列） |
| Prompts | `用途 + 提示词` | 主开发 Agent 五角色提示词（可直接复用） |
| 案例库 | `项目名（技术栈 / 规模补充）` | 某监控面板 + 消息调度，5 个 Agent 把活干完 |

**禁止**：`本篇方法1`、`总结`、`写作技巧`——无法检索、跨篇必然撞名、去重失效。

## 五、去重与淘汰

- **去重键**：同一「内容ID」+ 相同「素材名称」视为重复，写回工具一般会自动跳过并打印
  `已存在：…`。
- **跨内容去重**：工具通常只按「同内容ID + 名称」判重，跨篇重复要人工判断：
  - 新条目更完整 → 用带版本后缀的新名（如 `…（v2 补边界）`）另存，**不要覆盖**；
  - 只是措辞不同 → 不写，结果摘要里注明「与 XX 资产重复，未写」。
- **淘汰**：资产只增不删会出现「几十条里只有前 N 条被注入」。清理原则：
  1. 星级 ≤3 且长期未被任何选题引用 → 删；
  2. 同分类超过注入上限时，低星且描述最泛的排后面（不进前 N = 事实失效）；
  3. 删前看「备注」——写了「用在哪」说明还在服役，不删。

## 六、写回契约（关键：沉淀类动作不走普通单字段写回）

沉淀类动作的落点通常**没有绑定字段**（因为它不是「更新已有记录」，而是「素材库新增记录」）。

- **普通单字段写回对沉淀类无效**：值会静默丢弃或报错。
- 要用工作台提供的**素材库专用写回**（常见是写回工具的一个子命令）。

资产文件结构（示例）：

```json
[{"名称":"结构化输出不能只靠 Prompt（四层兜底）",
  "内容":"（前 60 字给结论）…",
  "类型":"工程方法论",
  "资产分类":"方法论",
  "星级":5,
  "备注":"适合放在踩坑节或收尾；做 AI 应用类内容通用"},
 {"名称":"「语法兼容不等于性能一致。」","内容":"…","类型":"观点金句",
  "资产分类":"金句","星级":5}]
```

写回工具一般已实现、**不要自己重写**的能力：按「同内容ID + 素材名称」去重、
非法分类退回该动作默认分类、缺名称/缺内容跳过、单次有**条数上限**（常见 5 条）、
写完自动把任务标记完成并写结果摘要。

- 先跑一次只读预览（`--dry`）看计划，确认没有意外的「跳过」项。
- `资产分类` 只能取该表实际枚举（常见为）：方法论 / 文章结构 / Prompts / 选题方法 /
  金句 / Skills / 案例库 / 素材库。
- 「内容ID」一般由工具从任务卡「目标键」自动带，**不要自己填**。
- 单条超长会提示「核心结论请前置」——是提醒，不是错误。
- 动作卡要求条数多于写回上限时（例如要 5–8 条但上限是 5），
  **只取自己判断最值得复用的那几条**，其余在结果摘要里列名称。
- **写库失败不影响任务结论**：在结果摘要注明「资产未沉淀」+ 原因。

## 七、写回前验收清单

1. 每条都过了「脱敏 / 可迁移 / 带触发条件 / 带证据锚点 / 不超长」五关
2. 分类与本动作默认分类一致（或明确归到别的分类并说明理由）
3. 名称符合命名规范，跨篇不会撞名
4. 星级已给（5 = 下篇必用 / 4 = 可选用 / ≤3 不如不写）
5. **前 60 字单独读也能看懂结论**（会被截断）
6. `--dry` 输出里没有意外的「跳过」项
7. 不超过写回条数上限
8. 金句逐字来自原文，没有编造
9. 结果摘要写清「沉淀了什么 / 哪些没写及原因 / 落到素材库哪几条」
10. 核对现状时按**能筛的键**核对（如果历史批量导入的资产「内容ID」为空，
    就改用「关联内容标题」，别按内容ID筛完得出「一条都没有」的错误结论）

## 八、常见坑

- **不要用普通单字段写回写沉淀**：落点字段为空，值会静默丢弃或报错。
- 素材库是「新增记录」，重复执行会产出重复条目；
  改名一个字就是新条目，所以**别在名称里加 `-最终版`**。
- 截断线是 200 字不是 300 字：200–300 字之间的后半段**注定看不到**。
- 不要把整篇总结塞进一条资产；宁可 3 条各 100 字。
- 别把选题判断写进方法论：选题判断归 `sed-topic`，写作手法归 `sed-method`。
- **提炼只从本篇正文里抽**，原文没有的方法 / 金句 / 案例不要编造。
- 如果历史资产是批量导入的（「内容ID」为空），注入时它们**也参与**——
  所以清理存量资产和写新资产一样重要。

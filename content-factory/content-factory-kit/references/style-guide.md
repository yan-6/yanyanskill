# 长出你自己的写作风格指南

`SKILL.md` 里那句话的兑现：**格式约定可以直接拿走，判断标准只能自己长。**
这份文档就是「怎么长」的动作手册——把你自己写过的那批作品，变成一份机器能读、
生成时能自动注入的风格指南。

配套工具：`scripts/measure_titles.py`（纯本地、零依赖，读你的语料出量化画像）。

---

## 一、先看一个反例：为什么别人的数字对你没用

同一批 248 篇的真实语料（一个技术博主的公开文章，2022–2026），
**全期平均**冒号率是 **44%**。看起来像「两段式是她的招牌写法，但不是每次都这样」。

按年份切开再看：

| 年份 | 篇数 | 长度中位 | 冒号率 | 问句率 | 栏目前缀率 |
|---|---|---|---|---|---|
| 2022 | 44 | 20.5 | 2.3% | 0% | 86.4% |
| 2023 | 25 | 21 | 0% | 0% | 100% |
| 2024 | 16 | 20 | 6.2% | 0% | 62.5% |
| 2025 | 107 | 31 | **64.5%** | 2.8% | 22.4% |
| 2026 | 56 | 33 | **67.9%** | 10.7% | **0%** |

同一批数据，结论完全不同：**她换过招牌**。2024 年之前是「【栏目前缀】+ 短标题」的
学习笔记体；2025 年起换成 30 字以上的两段式。全期平均 44% 这个数，
既不是她早期的样子，也不是她现在的样子——**它是一个不存在的中间状态**。

**结论：永远把结论下在「近期」那一行。** 全期平均只用来观察拐点，不用来定基准。

> 这份语料只是**示范怎么读数据**。你自己的数字得自己跑出来——
> 你是写两段式还是写问句，跟这个人一点关系都没有。

## 二、五个动作

### 动作 1 · 把语料凑齐

| 项目 | 要求 | 为什么 |
|---|---|---|
| 数量 | **≥ 80 条**，理想 150–300 | 30 条以下百分比会剧烈抖动，50% 和 30% 可能是同一批数据的随机波动 |
| 时间跨度 | **≥ 2 年**，且必须有日期 | 没有日期就看不到演变，只能得到一张静态照片 |
| 单一来源 | **只放你自己的、同一个笔名/账号的** | 混了合作稿或别人的稿，量出来的就不是你的风格 |
| 字段 | 至少「标题 + 日期」，能有正文更好 | 动作 3 要用正文 |

从哪来：平台后台导出、文章列表复制、RSS、或手动贴成一行一个。
**存成 CSV 最省事**（表头写 `标题,日期` 就能自动认得）。也支持
`json`（`[{"t":..,"d":..}]` / 字符串数组 / 带 `shelves` 的嵌套导出）、
`txt` / `md`（一行一个标题）。

```bash
python3 scripts/measure_titles.py 我的标题.csv
python3 scripts/measure_titles.py 我的标题.csv --words "让.*飞起来,全记录,实测"
python3 scripts/measure_titles.py 我的标题.csv --json > 画像.json
```

### 动作 2 · 量标题

跑完脚本，四个指标是必看的，每个都对应一个具体的写作决策：

| 指标 | 它回答什么问题 | 怎么用 |
|---|---|---|
| **长度中位** | 你的标题习惯装多少信息 | 中位 20 字和 33 字是两种完全不同的写法，别用错档 |
| **冒号率（两段式）** | 你的招牌句式是不是「主标题：副标题」 | 高 = 两段式是你辨识度的一部分，新标题就该是两段式；低 = 别硬套 |
| **问句率 / 数字率** | 你用不用悬念、用不用具体量级 | 近期问句率从 0% 涨到 11%，说明这是你新长出来的手法 |
| **栏目前缀率** | 老习惯有没有弃用 | 前缀从 100% 掉到 0%，说明你主动扔掉了这个标签 |

**然后一定要按年份切。** 脚本在有日期时会自动输出「分期演变」和
「早期合计 / 近期合计」两行，还会在冒号率翻倍时提醒你：
「近期是早期的 N 倍，说明你改过招牌写法」。

拿到分期表后做两件事：

1. **定位拐点年**——指标突然跳变的那一年。回想一下那年发生了什么（换平台？转型？接了商单？），
   把原因写在指南里。原因比数字重要，因为它决定这个变化会不会持续。
2. **只抄「近期」两列**进指南。早期数据留作对照，不要进基准。

> 脚本只给数字，不给结论。**「所以我的标题该写多长」这个判断是你的**，
> 脚本给的是你的历史事实。

### 动作 3 · 读你自己的全文（8 篇法）

标题只是入口。段落节奏、「你从不写什么」，只在正文里——这部分脚本量不出来。

**挑 8 篇**：跨体裁（长文 / 短记 / 教程 / 评测 / 随笔）× 跨年份（近两年 6 篇 + 老的 2 篇对照）。

**每篇只记 5 件事**，填这张表：

| # | 篇名 | ① 开头前 3 句在干什么 | ② 段落节奏（几句一段） | ③ 重复出现的口头禅/收尾词 | ④ **我从不写什么** | ⑤ 结尾怎么收 |
|---|---|---|---|---|---|---|
| 1 | | 场景钩子 / 结论前置 / 定义开场？ | 一句成段 / 3-6 句走逻辑？ | | | 回扣主题 / 互动提问 / 预告？ |
| … | | | | | | |

**第 ④ 栏是最值钱的一栏。** 8 篇读完它基本会自己浮出来——
比如「我从不写『综上所述』」「我从不排比」「我从不引用没打开过的链接」。
这一栏既是你判断「像不像 AI 写的」的依据（见动作 4 之后的第二节），
也是**最不可复制的一栏**：它记的是你的人，不是你的文体。

### 动作 4 · 定你的声道

「双声道」不是人人都需要，先判断你到底有几条：

- 翻一下动作 3 的 8 篇，**挑出最「端着」的一篇和最「放松」的一篇**。
- 对比三处：段落长度、人称频率（我 / 我 我 我）、有没有表情包或梗。
- **差异明显** → 你确实有两条嗓子，按题材分开写；
- **基本没差别** → 你只有一条，就写一条。**别为了像别人而硬造第二条**——
  硬造出来的第二条一般是「假装专业」，读者一眼看得出来。

写指南时**别用 A/B 命名**，用你自己认得的词（比如「给厂商的稿」/「自己玩的东西」）。
名字越贴身，越不容易写串。

混用的代价：**串味就是辨识度崩**。专业稿里冒出一句自嘲，或闲聊里冒出「赋能」，
两边都不成立了。

### 动作 5 · 写成文件，接进生成流程

写成一份 Markdown，推荐结构（这就是「创作小屋」工作台实际在用的那一份的骨架，
可以直接照搬）：

```markdown
# <你的笔名> 写作风格指南

> 数据来源：<N> 篇（<起> ~ <止>），深度精读 8 篇全文。
> 最后更新：<日期>

## 〇、速用指令（机器注入区，改这里全局生效）
<!-- DIGEST-START -->
你是「<笔名>」本人，所有产出必须像你亲手写的，严格遵守：
1. 声道选对：……
2. 标题：<你的长度区间><你的招牌句式>……
3. 开场 3 句内给钩子：……
4. 骨架：……
5. 节奏：……
6. 语气：……
7. 禁止：……
8. 收尾：……
<!-- DIGEST-END -->

## 一、一句话画像
## 二、量化画像（<N> 篇实测）      ← 数字全部来自动作 2 的输出，不要手写
## 三、声道模型
## 四、骨架
## 五、语气与词汇
## 六、反模式清单（我从不写什么）  ← 来自动作 3 的第 ④ 栏
## 七、速用模板
```

**`DIGEST-START` / `DIGEST-END` 这个约定很关键**：
工具会只抽这一段注入到所有生成提示词里。所以——

- **只把「每次生成都必须遵守」的硬规则放进去**，越长越容易被忽略；
- 改风格只改这一段，**不用改散落在别处的代码**；
- 前后标记必须成对，缺一半就抽不出来（会静默失效，不报错）。

### 动作 6 · 维护：按季度重跑，不按篇

- **每季度重跑一次** `measure_titles.py`，只改数字变了的行。
- **必须重跑的信号**：换了平台、换了体裁、停更后复更、接了商单。
- **不要每写完一篇就改指南**——那是噪声不是风格。风格是几十篇才看得出的东西。

## 三、量化之外：判断标准怎么长

量化给你骨架，但有三样东西**量不出来也抄不走**，只能靠积累：

| 要长出来的东西 | 怎么积累 | 为什么抄不了 |
|---|---|---|
| **什么话像 AI 写的** | 维护你自己的「我从不这么说」清单。起点可以用 `references/deai.md` 的通用清单，但**必须换成你实际见过的例子** | 别人列的词，你可能压根不写；你写的怪话，别人清单里没有 |
| **哪个标题配哪个平台** | 记录你每个平台实际发出去的效果（阅读 / 互动），几篇之后偏好自己就出来了 | 平台口味还会变，且和你的粉丝构成强相关 |
| **什么时候该缩小结论** | 记录你被打脸、被质疑、被要求改稿的时刻 | 这是经验，不是知识 |

这三样都没法从任何 skill 里拿到。**本文档给的是方法，结论必须是你自己的。**

## 四、常见坑（每一条都是真实踩过的）

| 坑 | 症状 | 正确做法 |
|---|---|---|
| 拿全期平均当基准 | 写出「有时两段式有时不是」的模糊结论，实际是换过招牌 | 结论只下在「近期」那一行 |
| 语料混了不同账号 / 笔名 | 指标被拉平，看不出任何一种真实风格 | 一个文件只放一个账号 |
| 语料太少 | 248 条里 44% 和 30 条里 50% 完全不是一回事 | 至少 80 条，最好带 2 年跨度 |
| 只量标题就以为掌握了风格 | 标题对了，正文还是 AI 味 | 必须做动作 3 的 8 篇全文精读 |
| 抄别人的结论 | 指南里写着「两段式」，但你从没写过两段式 | 抄结构，不抄结论 |
| DIGEST 标记缺一半 | 风格注入静默失效，生成结果完全不带你的风格 | 前后标记成对，改完抽查一次生成 |
| 把中文标点算漏 | 标题长度算成 25 字，实际含标点 30 字 | 长度按字符数（含标点）算，脚本已如此 |

## 五、交付前自查

- [ ] 语料 ≥ 80 条、跨 ≥ 2 年、带日期、**单一账号**
- [ ] 指标**全部来自脚本输出**，没有一个是手写的
- [ ] 分期表看过了，**拐点年**认得出，并记下了原因
- [ ] 结论只引用「近期」两列，早期只作对照
- [ ] 8 篇全文读完，**第 ④ 栏「我从不写什么」填满了**
- [ ] 声道数量是你**实际有的**，不是硬造的
- [ ] `DIGEST-START` / `DIGEST-END` 成对，且只装了硬规则
- [ ] 指南里**没有别人账号的数字**
- [ ] 用这份指南生成一篇，通读一遍，问自己「像不像我写的」

## 附：脚本用法速查

```bash
# 基本：出一份量化画像（含分期演变）
python3 scripts/measure_titles.py 我的标题.csv

# 指定列名（自动认不出来的表头）
python3 scripts/measure_titles.py 导出.xlsx.csv --title-field "文章标题" --date-field "发布时间"

# 加统计你自己的口头禅/句式（按正则匹配，忽略大小写）
python3 scripts/measure_titles.py 我的标题.csv --words "让.*飞起来,踩坑,全记录,实测"

# 输出 JSON，方便再喂给别的脚本或直接生成指南表格
python3 scripts/measure_titles.py 我的标题.csv --json > 画像.json

# 自检：30 项验收（不联网、不写外部账号）
python3 tests/check_measure_titles.py
```

支持 `csv` / `tsv` / `json` / `txt` / `md`。
`txt`/`md` 里以 `#` 开头的行按 Markdown 标题处理**默认跳过**（那是文档结构，不是文章标题），
行首的 `-` `*` `1.` 列表记号会被剥掉当标题。
